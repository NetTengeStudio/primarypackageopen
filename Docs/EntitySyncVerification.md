# Синхронизация при открытом живом редакторе — 2026-11-04

## Наблюдение и причины

Скриншоту соответствует `ConsoleLogs/DebugConsoleLog_Server_11042026_1936 (2).txt`: владелец долго подтверждает только событие 2796; после продвижения сервер получает ошибку `Missing item Рельсотрон (railgun)`, событие 4462, сущность 32763. Серверный снимок `ServerLogs/event_error_log_server_Хантер Лиггетт_1636.log` содержит добавленный редактором рельсотрон. Пользователь подтвердил создание через живой редактор.

Установлены три дефекта:

1. В `GameClient.Update(float)` выбор `SendIngameUpdate` зависит от `Screen.Selected == GameMain.GameScreen`. Открытый `LiveEditorScreen` не проходит это условие; клиент отправляет обновления лобби без игровых SyncIds. `ClientNetworkContext` меняет только эту проверку в сетевом Update: открытый живой редактор относится к работающему раунду. Настоящий Screen.Selected сохраняется.
2. Редакторские операции и native entity events передаются независимыми потоками. Доставка операции не означала её применение. Теперь Replica ждёт native-события до предоперационной отсечки, затем применяет операцию. Клиент подтверждает применённую ревизию; сервер ограничивает native-выдачу каждому клиенту отсечкой первой неподтверждённой операции. Снимок сначала создаёт сущности и объявляет готовность, после чего разрешается начальная синхронизация движка с отдельным пространством ID. Завершение снимка и подтверждение ревизии допускают перестановку пакетов.
3. Native `WriteEventErrorData` разыменовывает null в истории `EntitySpawner.receivedEvents`. Такая запись допустима при удалении уже отсутствующей сущности. `EventErrorDiagnostics` сохраняет запись как `<entity already absent> (unknown)` и позволяет штатному отчёту записать исходные ID ошибки. Исключения чтения сети не подавляются.

Протокол редактора повышен с 6 до 7 на существующем канале. Требуется одинаковое обновление сервера и всех клиентов. Данные Authority остаются источником истины для ревизий и отсечек; отдельная очередь копий событий не добавлена. Счётчик native-событий берётся из менеджера, а не выводится из последнего сохранившегося элемента списка.

В интеграции установлены 64 существующие клиентские цели Harmony; новые сетевой и диагностический патчи отдельно установлены целевым тестом. Сборка EntitySyncContracts — без предупреждений.
